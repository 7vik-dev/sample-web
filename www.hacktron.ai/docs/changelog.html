    November 8, 2026

    Platform

    • Hacktron in Slack now runs scripts in its own sandbox per thread, with web search, access to code hosts and package registries, and one-time approval for other hosts.
    • Hacktron in Slack now checks whether a CVE or advisory affects your repositories from their manifests and lock files, including transitive dependencies, and threads get three times the usage budget.
    • Hacktron in Slack can now set up pentests of public GitHub repositories from their URL, without you connecting them first.
    • Hacktron in Slack now reacts with eyes to each message it will reply to, and tells Slack Connect guests how to use Hacktron from their own workspace.

    November 5, 2026

    Review

    • Finding IDs such as ACME-FD-12 that you mention in a pull request description or comment now become links to the finding on GitHub, GitLab, Bitbucket, and Azure DevOps.

    • New Update check statuses in source control setting lets you turn off Hacktron check statuses on GitHub, GitLab, Bitbucket, and Azure DevOps separately from review comments.

    Platform

    • New Hacktron in Slack agent answers questions about findings, scans, your code, threat models, and the docs, and sets up pentests of repositories, code archives, and signed-in sites.

    • Hacktron in Slack can now review pull requests, generate fix pull requests, and, once you approve, change PR review settings, threat models, and applications, posting progress and results.

    • New On a schedule automation trigger starts whitebox scans daily, weekly, or monthly, reusing saved scope, login instructions, and a credit limit set up in the Whitebox scan wizard.

    • Findings with an open fix PR now show a Fix in review badge, and their activity lists pull requests, commits, and Slack messages that mention the finding’s ID.

    • Threat models now refresh daily at 03:00 UTC when the default branch changes, application models rebuild with their repositories, and one false-positive or accepted-risk decision triggers an update.

    • Log in, sign-up, and SSO pages are redesigned, with the email form first and Google, GitHub, and SSO below it, and password reset now has its own page.

      After

    API

    • You can now run a pentest through the API from draft to start, with POST /pentests, PATCH /pentests/{id}, POST /pentests/{id}/login-checks, POST /pentests/{id}/estimate, and POST /pentests/{id}/start.
    • New GET /pull-requests, GET /pull-requests/details, and POST /pull-requests/review endpoints list open pull requests and start a Hacktron review without anyone commenting on them.
    • New GET /pr-review-settings, PATCH /pr-review-settings, and POST /repos/pr-reviews endpoints let you read and change PR review settings, including scm_check_statuses_enabled, and turn reviews on or off per repository.
    • New POST /scans/{id}/stop stops a scan, POST /archives/uploads uploads a code archive, DELETE /pentests/{id} discards a draft, GET /credits returns your credit balance, and GET /findings/counts returns finding counts.
    • New POST /findings/{id}/remediate, GET /findings/{id}/remediation, and GET /credits/automation endpoints start a fix pull request for a finding, check its progress, and read automation credits.
    • New endpoints read and edit context documents, sync threat models, fetch pentest reports with GET /scans/{id}/report, open code checkouts with POST /code-workspaces, and manage applications with POST /applications.

    MCP

    • New MCP tools create_pentest_draft, update_pentest_draft, estimate_pentest, start_pentest, stop_scan, discard_pentest_draft, and request_archive_upload let you draft, price, start, stop, and discard pentests, including of code archives.
    • New verify_pentest_login tool checks that Hacktron can sign in to each site on a pentest draft, and drafts now accept login targets for signed-in testing.
    • The MCP server now has list_repositories, get_cost_estimation, get_credit_balance, and count_findings tools, so your assistant can see your repositories, cost estimates, credit balance, and finding totals.
    • New list_pull_requests, get_pull_request, and start_pr_review tools start reviews on GitHub, GitLab, Bitbucket, and Azure DevOps, and get_pr_review_settings, update_pr_review_settings, and set_pr_reviews change PR review settings.
    • New start_remediation, get_remediation, and get_automation_credit_balance MCP tools let your AI assistant generate a fix pull request for a finding, follow it, and check automation credits.
    • New MCP tools such as list_context_documents, read_context_document, get_pentest_report, open_code_workspace, edit_context_document, update_threat_model, and create_application let your agents read code and pentest reports, and edit threat models and applications.

    • New attestation letters give each customer a letter with a shareable link that opens without signing in, and a PDF.

    • Reports now list every deployed target and the accounts used to sign in.

    Review

    • Pull requests with up to 500 changed files are now reviewed, up from 200.
    • New Post system comments setting lets admins turn off notices about skipped reviews, usage limits, and configuration problems.
    • Each developer now gets 50 free reviews per approved open source repository each cycle, up from 30.
    • Auto-assignment now warns that bot authors take billable seats.

    October 21, 2026

    Whitebox

    • Retests now start from Request retest on a completed scan, cover every finding except false positives and accepted risk.

    • After a retest, Download report now offers the Original scan and After retest editions.

    Platform

    • A finding’s Activity tab now lists each detection and every edit with who made it, and Comments shows only the thread.
    • With a finding open, global search now leads with actions for it, such as Change status, Change severity, Copy ID, and Copy link.
    • Pasting two or more finding IDs into the findings search now filters to those findings, and global search now finds a finding by its ID.
    • The CWE badge on a finding now shows the weakness’s full name on hover.
    • Repositories now warns when PR Review is on but no trial or subscription is active, with Start free trial for owners.
    • Onboarding now connects GitHub, GitHub Enterprise Server, GitLab, Bitbucket, or Azure DevOps, and adds a Choose your repositories step.
    • Appliances that cannot reach GitHub.com now disable its setup and name the cause, such as DNS or TLS.
    • On appliances, the GitHub.com integration now shows webhook delivery health with Send test, and its PR reviews need a public HTTPS address.
    • Dynamic testing is now on for every appliance.
    • Appliances in managed pentest mode now show a cost estimate and a credit balance, and triage every pentest.

    API

    • List findings now matches repo_url regardless of case, a trailing slash, or a .git suffix.
